# 管理员内容访问边界审查（PR #28）

## 产品边界

普通账户只承载订阅授权，不是后台登录身份。新建普通账户后交付订阅或 Shadowrocket 链接，不生成激活链接、密码凭据或登录会话。订阅令牌只用于 `/api/sub/[token]`，不授予后台权限。管理员身份同时要求 `role=admin`、`isActive=true`、`isBanned=false`。

## 审查覆盖

- 六个后台页面：`/dashboard`、`/users`、`/configs`、`/monitor`、`/calendar`、`/settings`。
- 全部自建管理 API 的已导出 HTTP 方法，包括旧 users/configs/subscriptions/stats/logs/security-events、workspace 的各视图、订阅链接/额度/轮换、配置分配及认证方式删除。
- Better Auth 的普通密码拒绝、历史会话、资料/密码/绑定写入，及升级前 OAuth 状态，由 `z-admin-only.e2e.mjs`、`z-auth-concurrency.e2e.mjs`、`z-oauth-policy.e2e.mjs` 保留覆盖。
- 有意公开的订阅内容接口、返回 410 的旧激活入口，以及 Better Auth 通用路由单独测试，不把它们误算为未保护的管理接口。

`requireAdmin` 不依赖浏览器宣称的角色或缓存 cookie，先验证会话，再读取数据库中当前角色/启用/封禁状态。业务接口均在读取或写入业务数据之前调用守卫。后台布局有服务端守卫；设置页在序列化用户资料和会话 ID 前也独立重新检查权限，因为页面不能只依赖父布局拦截。

## 本次修复

1. 用户更新原先在事务外读取旧角色并决定是否升级。并发降级后，滞后的 `role=admin` 请求可能被当成普通管理员编辑，从而绕过新密码要求及历史认证清理。现在先在同一事务中锁定、重新读取用户，再判断升级并完成账户/通行密钥/会话清理。
2. PUT/DELETE 同时按 ID 稳定顺序锁定操作者和目标，重新确认操作者仍有管理员权限，阻止等待期间已被降级的操作者继续修改或删除账户。用户不存在、禁止自降级/自删除、保留可用管理员检查在事务中执行。
3. 设置页在把用户/会话信息送入 HTML 或 RSC 响应之前独立检查数据库权限。

不改变数据库结构、订阅令牌规则、客户端配置内容、安全扫描规则或生产环境。

## 新增回归

`tests/browser/z-admin-boundaries.e2e.mjs` 使用独立本地 `workspace_e2e` PostgreSQL 和真实生产构建 HTTP 服务，无伪造的成功接口响应。

- 从实际路由文件枚举方法，与拒绝矩阵比对；新增接口而未补矩阵时失败。
- 无登录、伪造 cookie、普通用户、已降级/停用/封禁管理员、过期会话、已删除账户共八种状态。
- 逐一检查所有管理方法返回 401/403 且只有错误字段；敏感测试标记、订阅令牌不得出现在响应中；比较前后数据库快照，拒绝操作不得产生业务副作用。
- 六个页面分别检查 HTML、完整 RSC 与实际浏览器导航的登录重定向及敏感信息缺席。Next.js 15 对动态路由的自动预取可只返回未渲染的路由骨架；测试仅接受精确的空 seed/head 响应结构，不把无内容预取误认为实际页面访问，也不接受任何账户或会话属性。每个页面均用浏览器确认未显示后台导航。另设有效管理员正向对照，避免“全部返回拒绝”被误认为通过。
- 三种等待并发降级的更新（无新密码升级、有新密码升级、只改密码），以及操作者被降级期间的 PUT/DELETE。测试观察 PostgreSQL `pg_blocking_pids` 中的真实等待者后才提交降级，不用固定睡眠假装制造竞态。

首轮 d44326f 的 208 次管理接口拒绝、五项并发回归及管理员正向对照通过；八项身份用例因错误要求自动预取必须重定向而在页面检查中失败。已改为分别严格检查完整 RSC 重定向、精确的无内容预取骨架，并扩大六页实际浏览器导航覆盖。最终是否通过以对应提交的 GitHub Actions 与上传 JSON 结果为准；此文描述测试覆盖，不代替执行结果。源码导出用临时工作流不在最终文件树。

## 发布与验证边界

本地隔离数据库验证不是生产验证。PR 合并、镜像发布、服务器拉取重启必须分别核实；旧生产镜像不会因分支修复自动改变。外部 GitHub 响应仍使用既有受控夹具，不能据此声称真实外部 OAuth、硬件通行密钥或 iPhone 真机已全部验收。已经合法下载到管理员浏览器的数据无法由服务端事后收回；本次防止未授权的新请求获取后台内容。
